# BILIM QUEST — GitHub Pages үшін дайын сайт

**BILIM QUEST** — қазақ тілі негізгі болып келетін білім беру квест платформасының статикалық нұсқасы. Орыс тілі де қолжетімді.

Сайттың негізгі файлы — **`index.html`**. Сайтты жариялау үшін сервер, Python немесе терминал қажет емес.

## 🌍 Сайтты GitHub-та жариялау (орысша нұсқаулық төменде)

1. Архивті компьютерге жүктеп, **ZIP-архивтен файлдарды шығарыңыз**. GitHub-та тек ZIP файлын жүктеп қою сайтты жарияламайды.
2. [github.com](https://github.com/) сайтына кіріп, аккаунт жасаңыз немесе кіріңіз.
3. Оң жақ жоғарғы **`+` → `New repository`** таңдаңыз.
4. Репозиторий атауын `bilim-quest` деп жазыңыз (өз атауыңызды да қоя аласыз), **Public** таңдаңыз, `Create repository` басыңыз.
5. Репозиторий ішінен **`Add file` → `Upload files`** таңдаңыз (егер бұл бос репозиторий болса, `uploading an existing file` сілтемесін ашыңыз).
6. Архивтен шығарылған **`index.html`**, **`.nojekyll`** (жасырын файл көрінбесе де `index.html` жеткілікті) және **`README.md`** файлдарын жүктеңіз. Оларды репозиторийдің **түбіріне** салыңыз, қосымша ішкі қалтаға емес.
7. Төменнен **`Commit changes`** басыңыз.
8. Репозиторийдегі **`Settings` → `Pages`** бөліміне өтіңіз.
9. **`Build and deployment` → `Source` → `Deploy from a branch`**, **Branch: `main`**, **Folder: `/(root)`**, **`Save`** таңдаңыз.
10. Бірнеше минут күтіңіз. Pages бөлімінде **`Visit site`** батырмасы және жария сілтеме көрсетіледі.

Жария сілтеменің түрі (үлгі ғана):

`https://GITHUB_ПАЙДАЛАНУШЫ_АТЫ.github.io/bilim-quest/`

Нақты мекенжай GitHub аккаунтыңыз бен репозиторий атауына байланысты.

## 🇷🇺 Как опубликовать сайт на GitHub Pages

1. **Скачайте и распакуйте ZIP**. Не загружайте ZIP на GitHub как единственный файл — так сайт не запустится.
2. Откройте [github.com](https://github.com/), войдите в свой аккаунт.
3. Выберите **`+` → `New repository`**, укажите название **`bilim-quest`**, выберите **Public** и нажмите **`Create repository`**.
4. В репозитории нажмите **`Add file` → `Upload files`**. Если репозиторий пустой, нажмите **`uploading an existing file`**.
5. Загрузите файлы из распакованной папки: **`index.html`**, **`README.md`**. Файл **`.nojekyll`** необязателен. Важно: файлы должны находиться **в корне репозитория**, а не во вложенной папке.
6. Нажмите **`Commit changes`**.
7. Откройте **`Settings` → `Pages`**.
8. В **`Build and deployment`** выберите **`Deploy from a branch`**, затем **`main`**, **`/(root)`** и **`Save`**.
9. Подождите несколько минут, затем нажмите **`Visit site`** в разделе Pages. Ссылку можно отправлять другим людям.

**Пример публичного адреса**: `https://ВАШ_ЛОГИН.github.io/bilim-quest/`. Реальный адрес будет известен после публикации.

### Что работает на GitHub Pages

- Интерфейс на казахском и русском, казахский по умолчанию;
- Выбор предмета, смена фона и анимаций;
- Разные виды заданий, загрузка изображения к заданию;
- Прохождение квеста, оценка из 10, доска почёта на главной странице;
- Рефлексия, экспорт результатов в **CSV** и **Excel**.

### ⚠️ Что важно понимать

GitHub Pages предоставляет **публичный адрес статического сайта**, но **не предоставляет общую базу данных, совместную сессию с QR-кодом или синхронизацию учеников**. В этой версии каждый посетитель видит **свои** данные, которые сохраняются в памяти **его браузера** (`localStorage`). Учитель, открывший сайт на другом устройстве, не увидит результаты учеников автоматически.

Чтобы собрать результаты на один компьютер, можно экспортировать CSV из каждого браузера и импортировать их в браузер учителя через кнопку на главной странице. Это ручной процесс; CSV не записывается в GitHub автоматически. Для общего рейтинга в реальном времени позже потребуется отдельный сервер и база данных.

**Конфиденциальность:** не выкладывайте в публичный репозиторий реальные имена, оценки, рефлексию или загруженные документы учеников. В архиве лежит только сайт и инструкция, реальные результаты не включены. Учитывайте, что ответные ключи и код этой статической версии доступны любому посетителю через исходный код страницы.

### Как обновить опубликованный сайт

Измените `index.html` и загрузите новую версию файла в тот же репозиторий, заменив старую. GitHub Pages автоматически опубликует изменения после обновления ветки `main`.

### Устранение неполадок

- **404 Not Found**: проверьте, что `index.html` находится в корне репозитория, а Pages настроен на `main / (root)`. Дождитесь завершения публикации.
- **Сайт открывается, но изменения не видны**: обновите страницу `Ctrl + F5`.
- **Ссылка не появилась**: зайдите в `Settings → Pages` и убедитесь, что источник публикации выбран, а вкладка `Actions` не показывает ошибку.
- **На другом устройстве пустая доска почёта**: это ожидаемо для статической версии; сохранение данных локальное.
